# znum -> zimrnum: the mapping

Generated by hand-verified enumeration, not inference. **This file is the answer to
"what is left"** - the roadmap in `zimrnum_plan.md` quotes it rather than guessing.

## The count

| | |
|---|---|
| znum numerics surface considered | 628 |
| present in zimrnum, incl. renames | **346** |
| **missing, every name read** | **130** |
| not yet triaged (`df`, top-level) | 152 |

**TRIAGED.** The 152 the scanner misattributed are three things, none a gap:

- **~70 GPU plumbing** - `createBindGroup`, `dispatch1D`, `readBuffer`, `packUniform`,
  `unaryKernelName`. znum dispatches kernels from inside the library; zimrnum compiles them as a
  separate artifact and the sweep is the interface. Not parity work, by design.
- **~20 znum test fixtures** - `predictXorF32`, `tanhSumLoss`, `targetCritics`.
- **~60 Tensor constructors and methods** - `zeros`, `ones`, `full`, `eye`, `arange`, `linspace`,
  `numel`, `item`. **These ARE real work.** The scanner missed them because it reads column-zero
  declarations, and zimrnum has these as methods or not at all. About 25 are genuinely absent;
  `zeros` and `ones` are `alloc` plus `fill`, `numel` is `size`.

So the target is **130 + ~25 = about 155 functions**, and `zimrnum_plan.md` accounts for every
one across twenty turns.
